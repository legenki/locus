## 2. Где omp уже сильнее и на что опираемся

- **`pi-ast`** (Rust, около 45 грамматик tree-sitter, `parse_cache`, `block_range_at`). Это основа индексатора и `edit_symbol`. Второй парсер не тащим.
- **hashline** (`crates/pi-edit/src/modes/hashline`). Уже умеет блочные операции: `PUT N*` / `CUT N*` берут синтаксический блок через `pi_ast::block`, включая декораторы и док-комментарии. Значит, правки «по целому узлу» в omp уже есть, но с адресацией **по строке и снимку**. `edit_symbol` добавляет адресацию **по имени**. Пересечение большое, разводим их явно в §3.5.
- **Пайплайн записи** (edit store, `file-mutation-queue`, approval, checkpoint/rewind, LSP writethrough, **ACP-роутинг в Zed**). `edit_symbol` обязан писать через него. Иначе в Zed правки обойдут `fs/write_text_file` и `request_permission`.
- **`bun:sqlite`** уже используется (`history-storage`, `agent.db`).
- **`packages/typescript-edit-benchmark`**: готовый стенд, чтобы сравнить `edit_symbol` и hashline.

## 3. Спецификация v0

### 3.1 Индексатор

**Где живёт.** Разбор и извлечение тегов в Rust (`crates/pi-ast`, новый модуль `tags`), экспорт через `pi-natives`. Хранилище, резолв импортов и граф в TS (`packages/coding-agent/src/locus/repomap/`). Причина: парсинг на горячем пути должен быть нативным, а резолв импортов проще итерировать на TS.

**Извлечение.** Используем `tags.scm`-запросы tree-sitter (`@definition.*` и `@reference.*`, формат Aider и GitHub code-nav). Для каждого файла получаем:

- **definitions**: имя, kind (`function | method | class | interface | type | enum | const | var | module | trait | impl`), qualified name (`Class.method`, `impl Foo` → `Foo.bar`), диапазон с учётом декораторов и док-комментов (те же правила, что у hashline-блоков), `exported`, однострочная сигнатура;
- **imports**: спецификатор и импортированные имена (binding → original);
- **references**: идентификаторы в позиции использования (call, type ref, member access), с привязкой к объемлющему определению, чтобы получить рёбра вызовов.

Языки v0 — те, для которых пишем извлечение тегов и резолвер импортов: **TS/JS, Rust, Go** (решено 2026-11-06; Python — v1). Файлы на остальных языках в v0 попадают в индекс только как файлы, без символов и рёбер.

**Резолв импортов.** TS/JS: относительные пути, `tsconfig.paths`, `package.json#exports` для workspace-пакетов. Rust: `mod`/`use crate::`. Go: префикс из `go.mod`. Не разрешилось → `external_imports` (пакет), в граф не идёт.

**Рёбра вызовов** (`calls`). `reference` внутри определения A → определение B, если имя B разрешается через import binding файла A или однозначно (одно экспортированное определение с таким именем во всём репо). Иначе `confidence = low` и ребро в PageRank не участвует. Угадывать не будем.

**Схема SQLite** (`<config>/locus/index/<repo-hash>.db`, WAL):

```sql
files(id PK, path UNIQUE, lang, size, mtime_ms, content_hash, line_count, pagerank REAL, indexed_at)
symbols(id PK, file_id FK, name, qname, kind, start_line, end_line, start_byte, end_byte,
        exported INT, signature TEXT, parent_id FK NULL)         -- idx(name), idx(qname), idx(file_id)
imports(file_id FK, specifier, resolved_file_id FK NULL, names TEXT)  -- idx(resolved_file_id)
refs(file_id FK, enclosing_symbol_id FK NULL, name, line)            -- idx(name)
edges(src_file FK, dst_file FK, weight REAL, kind TEXT, PRIMARY KEY(src_file, dst_file, kind))
calls(caller_symbol FK, callee_symbol FK NULL, callee_name, line, confidence)
meta(key PK, value)  -- schema_version, grammar_versions, last_full_scan
```

`ON DELETE CASCADE` от `files`. `schema_version` или смена версии грамматики → полный ре-индекс.

**Инкрементальность.** Здесь отходим от Empryo: у них только `mtime`, и после `git checkout` или `rebase` индекс молча врёт.

1. Быстрый путь: `(size, mtime_ms)` совпали → файл не трогаем.
2. Иначе считаем `xxh3` содержимого. Совпал `content_hash` → обновляем только `mtime`.
3. Иначе удаляем строки файла, заново парсим и вставляем в одной транзакции. Рёбра **в** этот файл не пересчитываем, а пересчитываем только **из** него. Входящие импорты по `resolved_file_id` остаются валидными, пока путь существует.
4. Удалённый или переименованный файл: удаляем строки, `imports.resolved_file_id` → NULL, при следующем резолве его ждёт `SET NULL`.
5. После пачки изменений PageRank пересчитывается лениво, при первом запросе карты, с warm start.

**Триггеры.**

- Старт сессии: фоновый скан. Карта доступна, пока идёт индексация, и помечается `partial`.
- Хук на собственные инструменты записи (`edit`, `write`, `edit_symbol`, `ast_edit`, `lsp rename`): ре-индекс конкретного файла с дебаунсом 150 мс.
- Перед каждым запросом `map` или `edit_symbol`: дешёвая сверка `stat` для файлов из фокуса. Для полного дерева — не чаще раза в N секунд. Так ловим `git checkout` и правки руками в Zed без отдельного fs-watcher. Watcher — в v1.
- Учитываем `.gitignore`, плюс лимиты: файлы > 1 МБ и сгенерированные файлы (`auto-generated-guard.ts` уже умеет их узнавать) пропускаем.

**Бюджеты.** Холодный индекс репо omp на M-серии за ≤ 30 с, в фоне и без блокировки TUI. Инкремент одного файла ≤ 50 мс.

### 3.2 Ранжирование

Схема Aider с поправками Empryo, которые нам нравятся.

**Граф** — ориентированный, вершины = файлы. Рёбра `src → dst`:

| Источник ребра | Вес |
|---|---|
| разрешённый импорт | `1.0 · √(кол-во использованных из dst имён)` |
| ссылка по имени на уникальный экспорт без импорта | `√refs · max(0.1, idf / ln N)`, ребро только при `idf > 0` |
| модификаторы имени | camel/snake и длина ≥ 8 → ×2 (Aider: ×10, начнём с ×2 и подберём). `_private` → ×0.1. Имя определено в > 5 файлах → ×0.1 |
| `dst` «type-heavy» (> 66% символов — interface/type/enum) | ×0.5, иначе файлы с типами доминируют |

**PageRank.** `d = 0.85`, до 20 итераций или пока `L1 < 1e-6`. Висячие вершины раздают ранг по вектору персонализации. Не-кодовые файлы (md, json, yaml) — в карте, но не в графе.

**Персонализация** (вектор телепорта, нормированный). Базовый вес `b = 1/N`, к нему добавляется:

- `+5b` — файлы, изменённые в этой сессии;
- `+3b` — файлы, прочитанные или упомянутые в последних K ходах, и файлы из `focus` запроса `map`;
- `+2b` — файл, открытый в Zed (берём из ACP-контекста, если клиент его передаёт);
- `+4b` — entry points (`package.json#bin/main`, `src/main.rs`, `main.go`, `__main__.py`);
- символы из `focus` дают `+3b` файлу-определению и `+1b` файлам с вызовами.

**Ранг символов.** Ранг файла раздаётся по исходящим рёбрам на конкретные определения пропорционально весу (как у Aider: ранжируются пары `(file, ident)`). Внутри файла символы сортируются по этому рангу, а у неэкспортированных он делится на 2.

Глобальный PageRank кэшируется в `files.pagerank`. Персонализированный считается на лету: на графе в 10k файлов с warm start это 2–3 итерации, < 30 мс.

### 3.3 Инструмент `map`

**Почему инструмент, а не инжект в каждый промпт, как в Empryo.** omp живёт на prompt caching. Карта, которая меняется на каждом ходу, сбрасывает кэш всего префикса, а это дороже, чем 2k токенов карты. Решение v0:

- **статический** срез (глобальный PageRank, ~1k токенов) один раз в system prompt на старте сессии, за настройкой `repomap.inject: "static" | "off"`, по умолчанию `static`;
- **персонализированный** срез только через вызов `map`.

**Параметры.**

```ts
map({
  focus?: string[],        // пути, глобы или "path::Sym"; пусто → вся карта
  budget?: number,         // токены, по умолчанию 2000, диапазон 256..8000
  importers?: string,      // путь: кто импортирует этот файл (режим importers)
  callers?: string,        // "path::Sym": кто вызывает (режим callers)
  depth?: 1 | 2,           // для importers/callers: прямые или +1 уровень
  include_private?: boolean // по умолчанию false
})
```

**Формат вывода** (для модели, экономный):

```
src/services/auth/session.ts  ←12  ★0.031
  class SessionManager                         L14-120
    refresh(token: string): Promise<Session>    L40-71
    revoke(id: SessionId): void                 L73-88
  fn createSessionStore(opts): SessionStore     L122-140
src/services/auth/index.ts  ←31  (barrel)
…
[map: 38 files, 1974/2000 tok, index: complete, 2s ago]
```

- `←12` — blast radius, число файлов, которые импортируют этот;
- `★` — ранг (только в debug-режиме, по умолчанию скрыт);
- `L14-120` — диапазон. Вместе с `path::Class.method` этого хватает, чтобы сразу звать `edit_symbol` или `read path::Sym` без грепа.

**Подбор под бюджет.** Бинарный поиск по числу символов из ранжированного списка, как у Aider. Токены оцениваем как `chars / 3.5`, а итоговую строку проверяем токенайзером из `pi-ai`, если он есть для текущей модели. Файлы из `focus` выводим всегда, даже если бюджет мал: урезаем их символы, но не выкидываем сам файл.

**Режим `importers`** — то, что на скриншоте Empryo:

```
importers of src/services/auth/session.ts (12 files, 31 refs)
  src/api/middleware/auth.ts        SessionManager, createSessionStore   ×7
  src/api/routes/login.ts           SessionManager                       ×4
  …
  via barrel src/services/auth/index.ts: 9 more files
```

**Режим `callers`**: то же самое по таблице `calls`. Рёбра `confidence = low` показываем отдельным блоком «возможно».

**Ошибки.** Индекс пуст или идёт сканирование → отдаём частичную карту с пометкой, а не ошибку. Путь вне репо → `ToolError`.

### 3.4 Инструмент `edit_symbol`

**Адрес**: `path::Qual.Name[#N]`

- `src/a.ts::parseConfig` — функция или переменная верхнего уровня;
- `src/a.ts::UserStore.fetch` — метод; вложенность через точку: `Outer.Inner.method`;
- Rust: `src/lib.rs::Foo.bar` ищет `fn bar` во **всех** `impl Foo` / `impl Trait for Foo`. Уточнение: `Foo<Display>.fmt` (impl трейта);
- `#N` — порядковый номер среди кандидатов (перегрузки TS, повторные `impl`). Его даёт сообщение об ошибке, сам по себе он неустойчив.

**Операции** (массив, атомарно на вызов: либо применяются все, либо ни одна):

```ts
edit_symbol({
  ops: [
    { op: "replace",       target: "src/a.ts::UserStore.fetch", code: "async fetch(id: Id) {…}" },
    { op: "insert_after",  target: "src/a.ts::UserStore.fetch", code: "async fetchMany(ids: Id[]) {…}" },
    { op: "insert_before", target: "src/a.ts::parseConfig",     code: "/** … */\nexport const DEFAULTS = {…};" },
    { op: "delete",        target: "src/a.ts::legacyHelper" },
  ],
  expect?: { [target: string]: string }  // необязательный хэш текста символа из map/read
})
```

**Семантика.**

1. **Резолв по текущему содержимому файла**, а не по индексу: файл парсится через `pi_ast::parse_cache`, индекс используется только для подсказок. Устаревший индекс не может привести к правке не того места.
2. **Диапазон символа** включает декораторы, атрибуты и прилегающий док-комментарий (правила `pi_ast::block`, общие с hashline). Отдельно стоящие `//`-комменты выше не входят.
3. **Ровно один кандидат → применяем.** 0 или > 1 → `ToolError`, файл не трогаем:

   ```
   edit_symbol: "src/a.ts::fetch" is ambiguous (3 candidates):
     src/a.ts::UserStore.fetch      method   L40-71   fetch(id: Id): Promise<User>
     src/a.ts::OrderStore.fetch     method   L130-160 fetch(id: Id): Promise<Order>
     src/a.ts::fetch                function L200-215 fetch(url: string)
   Use a qualified target.
   ```

   ```
   edit_symbol: symbol not found "src/a.ts::UserStore.fetchh". Closest: UserStore.fetch, UserStore.fetchMany
   ```

   Подсказки — по расстоянию Левенштейна, не больше 5 штук. Автоподстановки нет.
4. **`replace`**: `code` заменяет весь диапазон. Отступ первой строки `code` нормализуется к отступу цели, остальные строки сдвигаются на ту же дельту. Модель может писать код без учёта вложенности.
5. **`insert_before` / `insert_after`**: вставка как соседнего узла на той же глубине. Пустые строки между узлами — по стилю соседей: если соседи разделены одной пустой строкой, ставим одну.
6. **`delete`**: удаляет диапазон и схлопывает двойные пустые строки, получившиеся на стыке.
7. **Несколько ops в одном файле** применяются снизу вверх по позиции, чтобы смещения не ломались. Резолв всех целей делается **до** применения, по исходному тексту. Две операции над пересекающимися диапазонами → ошибка.
8. **Проверка синтаксиса после.** Новый текст парсится. Если ERROR- или MISSING-узлов стало больше, чем было до правки, вся пачка откатывается, а ошибка показывает фрагмент вокруг первой синтаксической ошибки.
9. **`expect`** — защита от гонок с ручными правками в Zed. Если хэш не совпал, получаем ошибку «символ изменился с момента чтения» и свежую сигнатуру. Без `expect` правим как есть: адресация по имени устойчива к сдвигу строк, и в этом её смысл.
10. **Запись** идёт через общий пайплайн `edit`: approval (tier `write`), checkpoint, `file-mutation-queue`, LSP writethrough и диагностика, ACP `fs/write_text_file`. После записи файл ре-индексируется.

**Ответ инструмента.** Компактный дифф по каждому символу, затем **hashline-заголовок `[PATH#TAG]` с новыми номерами строк изменённых символов**, затем LSP-диагностика (новые и исправленные ошибки). Модель может сразу продолжить точечной hashline-правкой внутри тела без повторного `read`.

**Где код.** Резолв адреса и вычисление диапазонов — в Rust (`pi_ast::symbols::resolve(code, lang, address) -> Result<Vec<Candidate>>`). Применение — через `pi-edit` как новый `EditSession`-источник, чтобы undo и store работали одинаково. TS-обёртка инструмента — в `packages/coding-agent/src/tools/edit-symbol.ts`, промпт — в `prompts/tools/edit-symbol.md`.

### 3.5 Связка с hashline: кто за что отвечает

| Ситуация | Инструмент |
|---|---|
| Переписать функцию, метод или класс целиком; удалить символ; добавить соседний символ | `edit_symbol` |
| Символ известен по `map`, файл ещё не читали | `edit_symbol` (читать не нужно) |
| Правка нескольких строк внутри тела | hashline `PUT N.=M` |
| Правка внутри тела сразу после `edit_symbol` | hashline с тегом из ответа `edit_symbol` |
| Импорты, конфиги, markdown, файлы без грамматики | hashline / `write` |
| Массовое переписывание по паттерну во многих файлах | `ast_edit` (ast-grep) |
| Переименование с обновлением ссылок | `lsp rename` |

В промптах инструментов: `edit` получает строку «целые символы → `edit_symbol`», а `edit_symbol` — «правки ≤ ~5 строк внутри тела → hashline, это дешевле по токенам».

Блочные операции hashline `PUT N*` и `CUT N*` остаются. Это тот же механизм, только адресация по строке. Если бенчмарк (§5) покажет, что модели путаются в двух способах, в v1 добавим в hashline адрес вида `PUT @Class.method*` и сольём оба способа в один.

## 5. Критерии приёмки v0

1. Холодный индекс репо omp ≤ 30 с, повторный старт без изменений ≤ 2 с, инкремент файла ≤ 50 мс (M-серия).
2. После `git checkout` на другую ветку первый вызов `map` отражает новое дерево. Есть тест на смену веток.
3. `map` с бюджетом 2000 не превышает 2000 токенов по токенайзеру модели. `focus`-файлы присутствуют всегда.
4. `map importers` для файла совпадает с `lsp references` по экспортам этого файла на выборке из 20 файлов (TS) с допуском по barrel-реэкспортам.
5. `edit_symbol` ни разу не правит не тот символ. Неоднозначность и not-found всегда дают ошибку. Есть фикстуры: перегрузки TS, декораторы TS, Rust с несколькими `impl`, методы Go на разных receiver, вложенные классы.
6. Синтаксически сломанный результат откатывается целиком.
7. В Zed (ACP) `edit_symbol` вызывает `session/request_permission` и пишет через `fs/write_text_file`.
8. `typescript-edit-benchmark`: на задачах «заменить или удалить функцию целиком» `edit_symbol` даёт ≥ hashline по успеху и меньше output-токенов. На мелких правках внутри тела модель продолжает выбирать hashline.

## 6. Решения

1. **Индекс** — в config-каталоге omp: `~/.omp/locus/index/<repo-hash>.db`.
2. **Языки v0** — TS/JS (включая TSX), Rust, Go. Python — v1.
3. **Форк, не PR.** Новый код держим изолированно, чтобы мерджи upstream оставались простыми:
   - Rust: новые файлы `crates/pi-ast/src/tags.rs` и `crates/pi-natives/src/tags.rs`, плюс одна строка `mod` в каждом `lib.rs`;
   - TS: всё в `packages/coding-agent/src/locus/`;
   - точки касания upstream-кода (регистрация инструментов, хуки записи) — минимальные, каждая помечена комментарием `locus:`.

## 8. Статус реализации (2026-11-06)

### Сделано

- **Индексатор.** `crates/pi-ast/src/tags.rs` обходит дерево tree-sitter для TS/TSX/JS, Go и Rust и достаёт символы, импорты и ссылки. Биндинги `extractTags`/`extractTagsAsync` лежат в `crates/pi-natives/src/tags.rs`. TS-слой находится в `packages/coding-agent/src/locus/repomap/`.
- **Резолв импортов:** относительные пути, перевод `.js` в `.ts`, `tsconfig.paths` (с `extends`), workspace-пакеты с `exports` (включая wildcard), Go-модули, Rust `mod`/`use crate::|self::|super::` и крейты workspace.
- **Граф и ранжирование:** рёбра `import` и `ref`, PageRank с персонализацией и warm start, ранг символов по входящим вызовам.
- **Инструмент `map`:** карта под бюджет, `importers`, `callers`, ошибки для неоднозначных и ненайденных целей со списком кандидатов и ближайших имён. Зарегистрирован как встроенный инструмент, документация в `docs/tools/map.md`.

### Замеры на репо omp

7.9k файлов, 294k символов, 959k ссылок. Linux, 4 ядра.

| Операция | Время |
|---|---|
| Холодный индекс | 30 с |
| Reconcile без изменений | 37 мс |
| Правка файла с 16 импортёрами (scoped, 45 файлов) | 0.7 с |
| Правка за популярным barrel (полная пересборка) | 4.3 с |

### Отличия от спека

1. **Нет fallback «уникальное имя во всём репо» и нет IDF-рёбер по имени.** На первом прогоне они дали сотни ложных рёбер: Rust-ссылки на `Error`/`Call` вели в Go-SDK, и Go-файлы оказались в топе карты. В TS, Go и Rust имя из другого файла требует импорта. Поэтому неквалифицированное имя — это локальное, из того же Go-пакета, из glob-импорта Rust или ambient-глобал из `.d.ts`. Только последний случай резолвится по уникальному имени. Вызовы через barrel идут по цепочке `export … from` до 6 уровней, с поддержкой алиасов.
2. **Вес ребра `import` = 1.** Остальной вес набирают разрешённые ссылки: `√count`, ×2 для длинных camel/snake-имён, ×0.1 для `_private` и для имён, определённых больше чем в 5 файлах.
3. **Инкрементальность.** У файла стабильный `id`. После правки пересчитываются только затронутые файлы: сам файл, его импортёры (через реэкспорты до 4 уровней) и файлы, вызывавшие его символы. Добавление или удаление файлов, смена конфигов и scope больше 10% репо ведут к полной пересборке. Тест проверяет, что scoped-результат совпадает с полной пересборкой.
4. **Две ловушки, на которые стоит обратить внимание:**
   - `glob` из natives отдаёт `size`/`mtime` только с `sortByMtime: true`;
   - FK без индекса на дочерней колонке превращает каскадное удаление в скан. На индексах `refs.enclosing_symbol_id` и `symbols.parent_id` время упало с 18 с до 8 мс.

### Второй этап (2026-11-06): всё из списка следующих шагов

- **`edit_symbol`** (`packages/coding-agent/src/locus/edit-symbol/`). Планирование — чистая функция: резолв по текущему тексту, переотступ, проверки пересечений, общей строки и синтаксиса. Запись идёт через встроенный `write`, поэтому approval, plan mode, LSP-формат и диагностика, ACP-мост и checkpoints работают как у обычной записи. Исходник читается из буфера Zed через ACP, если он подключён. Ответ содержит `[path#TAG]` и пронумерованные изменённые строки, и эти строки помечаются как увиденные. Тест подтверждает, что hashline-правка внутри нового тела проходит без `read`. От спека пока отложен необязательный `expect` (хэш символа): адресация по имени и чтение свежего текста при каждом вызове закрывают основной риск.
- **Свежесть.** Индекс сверяется перед каждым запросом (проход моложе 250 мс переиспользуется; холостой проход занимает около 40 мс). Это ловит собственные записи, правки в Zed и смену веток без отдельного watcher.
- **Прогрев.** Фоновый reconcile запускается при сборке инструментов сессии. Под `bun test` он пропускается, `LOCUS_REPOMAP=off` выключает его.
- **Персонализация по сессии.** Пути берутся из аргументов вызовов инструментов, которые ещё в контексте: правки дают +5, чтения +3, вес затухает до трети за 60 вызовов. Файл, открытый в Zed, пока не учитывается: в ACP нет стандартного поля для текущего файла, есть только @-упоминания в сообщениях.
- **Статический инжект.** Блок `<repo-map>` (~1000 токенов) в project prompt строится только из уже существующего индекса и никогда не ждёт индексации. Текст фиксирован на весь процесс, чтобы не сбивать prompt cache. Отрендеренная карта хранится в `meta` под версией графа. Отключается через `LOCUS_REPOMAP_INJECT=off`.
- **Найденные и исправленные баги:**
  - новый процесс всегда делал полную пересборку графа: ключ конфигов жил только в памяти. Теперь он хранится в `meta`, и повторный старт на omp занимает 77 мс;
  - ключ конфигов не учитывал содержимое, и правка `paths`/`exports` не замечалась. Теперь в ключе size и mtime.
- **Рендер:** глобальная карта 35 мс (было 85), с фокусом и бустами 62 мс (было 150). Стоимость считается одним проходом префиксных сумм вместо бинарного поиска, кандидаты отбираются через typed arrays.
- `INDEX_SCHEMA_VERSION` = 2: изменился формат сигнатур, поэтому старые индексы пересоберутся.
